# Инструкция для получателя проекта

**Проект:** «Культурная карта Санкт-Петербурга» — веб-сервис с интерактивной картой
474 культурных объектов Центрального района, поиском, пространственными запросами
и ИИ-помощником на естественном языке.

Этот файл — короткая дорога от «архива у меня» до «сервис работает в браузере».

---

## 1. Что вам нужно иметь

| Что | Зачем | Обязательно? |
|---|---|---|
| **Docker Desktop** (Windows/macOS) или Docker Engine + Compose (Linux) | запуск всей системы тремя контейнерами | **да** |
| ~5 ГБ свободного места | образы контейнеров + модель ИИ | да |
| **Ollama** + модели `qwen2.5:7b`, `nomic-embed-text` | ИИ-помощник и семантические рекомендации | нет, см. п. 5 |
| Браузер | открыть интерфейс | да |

Python, Node.js и PostgreSQL **устанавливать не нужно** — всё работает внутри контейнеров.

---

## 2. Быстрый старт

```bash
# 1. Распакуйте архив и войдите в папку
cd group_proj

# 2. Запустите (первый раз — с пересборкой образов, ~2-5 минут)
docker compose up -d --build

# 3. Дождитесь готовности
docker compose ps        # все три сервиса должны быть healthy/running
```

**Откройте в браузере: <http://localhost:3000>**

Готово. Данные загружаются автоматически — ручные команды импорта не нужны.

> База данных заполняется при самом первом старте из файла `db/init/02-data.sql`.
> PostgreSQL выполняет скрипты из `db/init/` только когда том данных пуст, поэтому
> на уже работающей системе повторный запуск ничего не перезаписывает.

---

## 3. Проверить, что всё работает

```bash
curl http://localhost:8000/api/health
```

Ожидаемый ответ:

```json
{"status":"ok","database":"ok","postgis_version":"3.6 ...","pgvector":true,
 "objects_count":474,"districts_count":1,"ai_available":true,...}
```

- `objects_count: 474` — данные на месте
- `ai_available: true` — ИИ подключён (см. п. 5)

Также доступны:
- **Swagger-документация API** — <http://localhost:8000/docs>
- **Статические страницы фронтенда** — <http://localhost:3000>

---

## 4. Если база уже была пустой (ручной импорт)

Обычно это не требуется. Но если `objects_count: 0`:

```bash
docker compose exec backend python scripts/import_data.py
```

Для работы семантического поиска и рекомендаций нужны вектора (нужна Ollama):

```bash
docker compose exec backend python scripts/generate_embeddings.py
```

## 5. Подключение ИИ-помощника (Ollama)

ИИ работает **локально**: ваши запросы никуда не отправляются.

```bash
# Установите Ollama: https://ollama.com/download

ollama serve                      # запуск сервера (отдельное окно терминала)
ollama pull qwen2.5:7b            # модель разбора запросов (~4,7 ГБ)
ollama pull nomic-embed-text      # модель эмбеддингов (~270 МБ)
```

Docker-контейнер обращается к Ollama на хосте по адресу
`http://host.docker.internal:11434` — он задан в `docker-compose.yml` по умолчанию.

**Без Ollama сервис полностью работоспособен:**

- карта, фильтры, поиск, радиусные запросы, статистика, избранное — всё работает;
- `/api/health` покажет `status: "degraded"` и `ai_available: false`;
- запросы к `/api/query` обрабатываются **шаблонным разбором** (регулярные выражения)
  и помечаются в ответе: *«(запрос разобран шаблонами: AI-модель недоступна, §53)»*;
- если шаблоны не справились — ответ `503` с подсказкой переформулировать запрос.

После установки Ollama перезапускать контейнеры не нужно — подключение проверяется
автоматически (кэш доступности 10 секунд).

## 6. Полезные команды

```bash
docker compose logs -f backend    # логи API в реальном времени
docker compose logs -f db         # логи PostgreSQL
docker compose ps                 # состояние контейнеров
docker compose restart backend    # перезапуск API (например, после смены настроек)

docker compose exec db psql -U culturalfind -d culturalfind \
  -c "SELECT count(*) FROM cultural_objects;"   # проверить данные

docker compose down               # остановить (данные сохраняются в томе)
docker compose down -v            # остановить И УДАЛИТЬ данные (дальше п. 4)
```

**Остановка с сохранением данных:** `docker compose down` — том `pgdata` остаётся,
при следующем старте данные не потеряются.

## 7. Настройка (необязательно)

Все параметры задаются через переменные окружения. Значения по умолчанию
работают «из коробки»; чтобы что-то изменить, скопируйте шаблон:

```bash
cp .env.example .env
```

Основные настройки в `.env`:

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `BACKEND_PORT` | `8000` | порт API |
| `FRONTEND_PORT` | `3000` | порт веб-интерфейса |
| `AI_ENABLED` | `true` | отключает ИИ-модуль целиком (`/api/query` → 503) |
| `AI_BASE_URL` | `http://host.docker.internal:11434` | адрес Ollama |
| `AI_MODEL` | `qwen2.5:7b` | модель разбора запросов |
| `MAX_RADIUS_METERS` | `10000` | ограничение радиуса поиска (10 км) |
| `MAX_LIMIT` | `100` | максимум объектов в выдаче |
| `SCORE_WEIGHT_SEMANTIC` | `0.5` | вес семантики в рекомендациях |
| `SCORE_WEIGHT_SPATIAL` | `0.3` | вес пространственной близости |
| `SCORE_WEIGHT_CATEGORY` | `0.2` | вес категории |

После изменения `.env` перезапустите backend:

```bash
docker compose up -d backend
```

## 9. Возможные проблемы

| Симптом | Причина | Решение |
|---|---|---|
| `port is already allocated` | порт занят другой программой | измените `BACKEND_PORT`/`FRONTEND_PORT` в `.env` |
| Страница не открывается сразу после старта | контейнеры ещё поднимаются | подождите 30–60 секунд, проверьте `docker compose ps` |
| `ai_available: false`, статус `degraded` | Ollama не запущена или не скачаны модели | см. п. 5 |
| Карта пуста, `objects_count: 0` | том базы без данных | см. п. 4 |
| Ошибка `relation "cultural_objects" does not exist` | миграция не выполнилась | `docker compose logs backend`, затем `docker compose restart backend` |
| Карточки объектов без картинок | нет доступа к Wikimedia Commons | нужен выход в интернет для загрузки миниатюр |

## 10. Структура проекта

```
group_proj/
├── backend/          FastAPI: API, пространственные запросы, AI-модуль (pytest)
│   ├── app/
│   │   ├── api/      REST-эндпоинты (17 шт.)
│   │   ├── spatial/  SQL к PostGIS: радиусы, ближайшие, поиск, аналитика
│   │   ├── ai/       парсер LLM, резолвер мест, рекомендации, fallback
│   │   ├── models/   SQLAlchemy-модели
│   │   └── schemas/  Pydantic-схемы ответов
│   ├── alembic/      миграции схемы
│   └── tests/        69 тестов
├── frontend/         React + TypeScript + Vite + Leaflet
│   └── src/
│       ├── components/  карта, панель фильтров, AI-панель, поиск, карточка
│       ├── pages/       страница объекта (/object/:id)
│       └── api/         клиент API
├── db/               образ PostgreSQL + PostGIS + pgvector
│   └── init/         01-extensions.sql, 02-data.sql (данные)
├── scripts/          ETL: загрузка и обогащение данных
├── data/
│   ├── processed/    objects.json, locations.json, landmarks.json
│   └── raw/          district_polygon.json (граница района)
├── docs/             документация и план презентации
├── docker-compose.yml
└── README.md
```
